New since 0.3.0

Three releases about trust: your drives, your edits and your index behave the way you'd expect, even when files move under them.

Unplugged is not deleted

Images on a drive that's unplugged, or behind file-chooser access that has expired, are set aside rather than written off. Plug the drive back in and they return as they were, with their tags and stars and without re-indexing. 0.4

Changed elsewhere, shown fresh

Edit or rotate an image in another app and both the thumbnail and the full-size viewer show the new version. Thumbnails are checked the way GNOME checks them, and written so an interrupted write can't leave a broken one. 0.4

Saving is safe

Saving an edited image keeps the tags and ratings of every copy of it. Save in place is offered only for JPEG and PNG, other formats go through Save As, and a failed save tells you. 0.3.2

Its own thumbnail cache

The large grid sizes get a private cache that can't crowd out Files' thumbnails. Preferences → Clean Up Thumbnails… shows what each cache holds and clears it by age. 0.3.1

A leaner index

One-time cleanups remove entries that never belonged in the index, such as thumbnail caches and folders that no longer exist. A backup is taken first, and anything tagged, rated or collected is kept. 0.3.1, 0.4

Fixed

The icon size is remembered. Opening one folder while another is still loading lands on the right one. The filter bar keeps your tag. "Indexing…" stays up until the last folder finishes. Collection counts and rating filters are much faster on large libraries.

What it does

Browse, view, review, organize, edit and de-duplicate — all keyed to survive renames.

Fast browsing

Virtualized grid with rubber-band selection, adjustable thumbnails, and bounded caches that stay flat on 27k-image folders. Reuses GNOME's shared thumbnail cache, and keeps a separate one for USB and network drives.

Beautiful decoding

AVIF, JXL, HEIF, and the classics via glycin — color-managed, EXIF-oriented, decoded in sandboxed subprocesses. Sharper than gdk-pixbuf thumbnails.

Viewer & filmstrip

Fit / zoom / pan / 100%, arrow-key navigation, a synced filmstrip, and a live properties panel (dimensions, camera, date, format) with an optional histogram.

Review layer

0–5 star ratings (with keyboard shortcuts and thumbnail overlays), free-text comments, and tags you add to — or remove from — a whole selection at once.

Collections

Hand-curated catalogs (drag images in, reorder) and smart collections — a saved filter that keeps itself up to date.

Rename-proof index

A background SQLite catalog keyed by BLAKE3 content hash. Move or rename a file and its tags, rating, comment, and collection memberships follow the bytes.

Find duplicates

Exact (byte-identical) and near (perceptual-hash) clustering, scoped to the folder you're in, with a reclaimable-space readout. Trashing the extra copies asks first.

Nautilus-style navigation

A switchable sidebar — bookmarks, a folder tree, and collections — plus Back/Forward history and a filter bar with fuzzy find by name.

Your own sort orders

Name, size, date, type, rating or date taken — or any order you can write as a few lines of Lua, reloaded live as you edit it.

Interoperable

Export XMP sidecars (xmp:Rating / dc:description / dc:subject) so digiKam, darktable, Lightroom, and XnView read your ratings, comments, and tags. Originals are never rewritten.

Install

Not on Flathub — Vitrine ships from its own signed Flatpak repo. The GNOME 50 runtime comes from Flathub automatically.

Recommended — the signed repo (gets flatpak update)

flatpak install --user https://superuser-miguel.github.io/vitrine-repo/vitrine.flatpakref
flatpak run io.github.superuser_miguel.Vitrine

Or open vitrine.flatpakref with GNOME Software. Either way, one step adds the remote and installs the app, so new versions arrive with a normal flatpak update — or GNOME Software's updates. The repo is GPG-signed, and flatpak checks every update against the key embedded in the .flatpakref.

Alternative — the offline bundle

A Vitrine.flatpak bundle is also attached to the latest GitHub release, for offline or air-gapped installs:

flatpak install --user ./Vitrine.flatpak

A bundle has no origin to pull from, so flatpak update can't upgrade it — moving to a newer version means downloading the next bundle by hand. Prefer the repo unless you specifically need a single offline file.

Installed 0.1.0 or 0.2.0? Those came as bundles, so they'll never update on their own. Switch to the repo once:

flatpak uninstall --user io.github.superuser_miguel.Vitrine
flatpak install --user https://superuser-miguel.github.io/vitrine-repo/vitrine.flatpakref

Your index, tags, ratings, comments, collections, bookmarks, scripts and settings are kept: they live in ~/.var/app/io.github.superuser_miguel.Vitrine/, which a plain uninstall leaves alone (just don't add --delete-data). From then on, flatpak update keeps you current.

Roadmap

Honest about where it's headed. v0.4.0 is out now. (The stories behind the hard parts are in the Vitrine blog.)

Shipped in 0.3.1 – 0.4 — trust what's on screen

  • Offline-aware index — unreachable files are parked and retried, drives plugged back in are recognised, and an unmounted drive isn't mistaken for an empty folder.
  • Invalidation — thumbnails and the viewer follow changes made by other apps.
  • Safe saving — annotations survive Save, with no wrong formats and no silent failures.
  • A private thumbnail cache and Clean Up Thumbnails in Preferences.
  • A leaner index — cache rows and dead file-chooser entries cleaned up once, with a backup.

Shipped in 0.3.0 — find, measure, and remember

  • Fuzzy find — by name and path, from the filter bar, ranked best match first.
  • Histogram — luminance and RGB in Image Properties.
  • Thumbnails for removable drives — kept between sessions, recognised by content across mounts. How it knows a file is on a USB →
  • Lua sort scripts — custom orders in the Sort By menu, reloaded live, with starter scripts.
  • Bulk tag removal — an Add / Remove toggle in the grid's Tag popover.
  • Smoother under load — no blank cells after a fling, visible thumbnails first on cold opens, the grid standing down while the viewer is up. Blank cells → · Decode order →
  • Signed update channel — install once from the .flatpakref; updates arrive with flatpak update.

Shipped in 0.1 and 0.2

  • Browse · view · index — grid, viewer, filmstrip, content-hash catalog.
  • Review & organize — ratings, comments, tags, collections, filter bar.
  • Find duplicates — exact and perceptual-hash clustering, scoped to the open folder.
  • Navigation — switchable sidebar, bookmarks, folder tree, Back/Forward.
  • XMP sidecar export — ratings/comments/tags out to .xmp for other tools.
  • Edit tier — non-destructive rotate / flip / crop with undo/redo and Save / Save As.
  • Decode-scheduling performance — viewport-ordered, cost-aware thumbnail loading.
  • Removable-media bookmarks — offline state for USB drives that come and go.

Later

  • Viewer pan — grab-hand click-drag panning for zoomed-in / large images.
  • Deeper editing — resize / straighten and GPU-accelerated adjustments.
  • More navigation — address bar and tabs.
  • More scripting — batch ImageMagick operations and rename rules, on top of the sort scripts that ship today.
  • WASM plugins — local auto-tagging and embedding-based "find similar".
  • In-file XMP embed — write the packet directly into JPEG/PNG containers.

Writing

Notes from building it — newest first. All posts →

Is this file on a USB?

A slow external drive shouldn't re-decode its thumbnails every visit — but caching them means knowing a file is on removable media, and inside a Flatpak sandbox /run/media is invisible and the path is an opaque doc id. One extended attribute, document-portal.host-path, answers it.

Blank cells, warm cache

Fling a big folder to a dead stop and the visible thumbnails stay blank for a minute — while their decoded textures sit warm in the RAM cache the whole time. A load queue capped at its newest 400, and a grid that binds so far ahead of the viewport that the rows you're staring at are the oldest, and the first evicted.

The viewport that lied

A big folder that felt like it opened in the middle — three rebuilds and one confidently wrong fix, ended by a single line of instrumentation. The decoder was inferring the viewport from the wrong thing — and the loose end ran down to a 60-line GTK reproducer: 32 × columns + 1.

What the document portal actually does

A hands-on tour of Flatpak's document portal — the FUSE mount, the D-Bus registry, directory grants, and the three states a sandboxed app has to tell apart. With numbers from a real 193,000-file library.

Six bugs in an image browser

A debug log that couldn't see its own bugs, a tag menu that got slower the more you used it, Flatpak portal paths that aren't paths — and the diagnoses that were confidently wrong.

The duplicate that was one file

Find Duplicates reported 41,727 duplicates that mostly weren't. Sandbox path aliases, a trash button that lied, two five-minute experiments — and why "duplicate" turned out to be a product decision with a one-field fix.

Build & run

Flatpak: the GNOME 50 SDK. Host builds: GTK4, libadwaita, a Rust toolchain and blueprint-compiler. Details in the README.

# Flatpak (recommended)
flatpak-builder --user --install --force-clean build-dir \
  build-aux/io.github.superuser_miguel.Vitrine.yml
flatpak run io.github.superuser_miguel.Vitrine

# Or a plain cargo dev build
cargo run -p vitrine-app
